### 들어가며

LLM 관련 문서를 읽다 보면 "Fine-tuning 대신 Few-shot으로 간다", "Many-shot CoT 학습데이터", "QLoRA 경량 튜닝" 같은 말이 한 문단에 섞여 나온다. 특히 **"Few-shot 학습"이라는 말 때문에 Fine-tuning과 같은 종류로 착각하기 쉬운데, 둘은 전혀 다른 방법**이다. 용어들이 각각 어디에 속하는지부터 정리해본다.

(토큰, 컨텍스트, 파라미터 같은 기초는 [LLM 기본 개념 정리](/posts/LLM-기본-개념-정리-토큰-컨텍스트-파라미터-GPU-메모리/) 글에 따로 정리해뒀다.)

### 1\. 큰 그림 - 두 갈래로 나뉜다

```
LLM을 원하는 대로 동작하게 만드는 방법
│
├─ A. 모델 자체를 바꾼다 (Training)
│    ├─ Foundation 모델, Weight          ← 바꾸는 대상
│    ├─ Fine-tuning                       ← 추가 학습
│    └─ 경량 Fine-tuning (LoRA, QLoRA)    ← 일부만 학습
│
├─ B. 모델은 그대로, 입력(프롬프트)을 바꾼다 (In-context Learning)
│    ├─ Zero-shot / Few-shot / Many-shot  ← 예시 개수
│    └─ CoT                                ← 생각하는 방식 지시
│
├─ C. 외부 지식을 찾아서 입력에 넣는다
│    └─ RAG
│
└─ D. B·C에 넣을 재료 (데이터 자산)
     └─ Gold Example, CounterExample, 교정규칙
```

핵심 구분은 **가중치(Weight)가 바뀌느냐**다. A만 모델을 바꾸고, B·C·D는 모델을 그대로 두고 **입력을 잘 만드는 방법**이다.

#### 신입사원 비유

-   **A. Fine-tuning**: 연수원에 보내 교육시킨다. 배운 게 머리에 남지만 시간과 돈이 들고, 사람이 바뀌면 다시 보내야 한다
-   **B. Few/Many-shot**: 일을 시킬 때마다 "이렇게 하면 되고, 이렇게 하면 안 돼"라는 예시를 같이 준다. 머리는 그대로지만 바로 적용된다
-   **C. RAG**: 일을 시킬 때 관련 자료를 찾아서 같이 건네준다
-   **D. Gold / Counter**: B와 C에서 건네줄 모범 답안과 오답 노트

### 2\. A - 모델 자체를 바꾸는 방법 (Training)

| 용어 | 개념 |
|---|---|
| **Foundation 모델 (기반 모델)** | 대규모 데이터로 미리 학습된 범용 LLM. GPT, Claude, Llama 같은 원본 모델 |
| **Weight (가중치)** | 모델 안의 숫자들. 모델의 지식 그 자체. "파라미터"와 같은 말 |
| **Training (학습)** | 데이터를 보여주며 가중치를 조정하는 과정. **모델이 실제로 바뀐다** |
| **Fine-tuning (미세조정)** | 이미 학습된 모델을 특정 목적의 데이터로 **추가 학습**시키는 것 |
| **SFT (지도 미세조정)** | "질문 → 정답" 쌍(Instruction Dataset)을 보여주며 Fine-tuning하는 가장 흔한 방식 |
| **PEFT (효율적 미세조정)** | 모델 전체가 아니라 일부만 학습하는 방법들을 통칭 |
| **LoRA** | 원래 가중치는 얼린 채, 옆에 붙인 **작은 어댑터 모듈만** 학습. 학습량·저장 공간이 크게 줄어든다 |
| **QLoRA** | 원본 모델을 4비트 등으로 **양자화해서 메모리를 아낀 상태**로 LoRA를 하는 방식 |

#### 장점

-   원하는 말투·형식·판단 방식이 **모델에 배어든다**
-   매번 긴 예시를 넣지 않아도 되니 **호출할 때 입력이 짧다**

#### 단점

-   **품질 좋은 학습 데이터**를 많이 만들어야 한다
-   GPU, 시간, 검증 비용이 든다
-   **모델을 교체하면 다시 학습**해야 한다 (새 모델이 자주 나오는 요즘 특히 부담)
-   학습 데이터에 민감 정보가 있으면 **가중치에 흡수**돼서 통제하기 어렵다

### 3\. B - 모델은 그대로, 입력을 바꾸는 방법 (In-context Learning)

| 용어 | 개념 |
|---|---|
| **In-context Learning (문맥 내 학습)** | 가중치를 바꾸지 않고, **프롬프트에 넣은 예시와 지시만으로** 모델이 패턴을 따라 하게 만드는 것 |
| **Zero-shot** | 예시 없이 지시만 준다 |
| **One-shot** | 예시 1개 |
| **Few-shot** | 예시 몇 개 (보통 2~10개 안팎) |
| **Many-shot** | 예시를 수십~수백 개. **컨텍스트가 긴 최신 모델**에서 가능해진 방식 |
| **CoT (Chain of Thought)** | 답을 바로 내지 말고 **단계별로 추론하게** 지시하는 기법 |
| **Few-shot CoT / Many-shot CoT** | 단계별 풀이 과정이 담긴 예시를 넣어서, 추론 방식까지 따라 하게 하는 것 |

#### 가장 헷갈리는 포인트: 이건 "학습"이 아니다

이름에 Learning이 붙어 있고 "Few-shot 학습"이라고도 부르지만, **실제로 모델이 학습(Training)되는 게 아니다.** 호출이 끝나면 모델은 예시를 다 잊는다. 다음 호출에도 같은 행동을 원하면 **예시를 또 넣어야** 한다.

그래서 어떤 문서는 일부러 **"In-context Behavioral Learning"**, 즉 "가중치가 아니라 입력으로 **출력 행동**을 유도하는 것"이라고 구분해서 쓰기도 한다.

#### 장점

-   **바로 적용**된다. 예시만 바꾸면 행동이 바뀐다
-   **모델을 바꿔도 예시·규칙을 그대로 재사용**할 수 있다
-   데이터가 적어도 시작할 수 있다

#### 단점

-   매번 예시를 넣으니 **컨텍스트 한도와 호출 비용**을 먹는다
-   모델에 완전히 배어들지는 않아서, 복잡한 형식은 가끔 흔들린다
-   예시를 **잘 고르는 것**이 성능을 좌우한다

### 4\. C - 외부 지식을 넣는 방법 (RAG)

| 용어 | 개념 |
|---|---|
| **RAG (검색 증강 생성)** | 질문과 관련된 자료를 **검색해서 프롬프트에 넣어 주는** 방식. 모델은 그대로 둔다 |
| **Few-shot RAG (예시 검색)** | 자료뿐 아니라 **예시도 검색해서** 넣는 것. 미리 쌓아둔 예시 중 **이번 요청과 가장 비슷한 것**만 골라 넣는다 |

-   B가 "어떻게 답할지(행동)"를 알려준다면, C는 "무엇을 근거로 답할지(지식)"를 알려준다
-   예시가 수백 개 쌓이면 다 넣을 수 없으니, **RAG로 예시를 골라 넣는 방식**이 B와 C를 합친 형태로 많이 쓰인다

### 5\. D - B·C에 넣을 재료

Few-shot을 제대로 하려면 **"좋은 예시"만 넣는 것으로는 부족**하다. 실패 사례까지 같이 넣으면 "하면 안 되는 것"도 알려줄 수 있다.

| 용어 | 개념 | 비유 |
|---|---|---|
| **Gold Example** | 전문가가 승인한 **모범 답안** | 모범 답안지 |
| **CounterExample** | AI가 **틀린 사례**와 틀린 이유 | 오답 노트 |
| **Corrective Rule (교정규칙)** | 틀린 사례에서 뽑아낸 **금지 규칙** | "이 실수는 다시 하지 마라" 메모 |

예를 들어,

-   **Gold**: "이 문서의 요약은 이렇게, 근거 문장은 이것"
-   **Counter**: "원문에 없는 내용을 근거로 들었다 → 실패"
-   **교정규칙**: "원문에서 근거 문장을 찾을 수 없는 내용은 답에 쓰지 않는다"

그리고 이 재료들은 **사람이 검토한 결과로 계속 쌓인다.** AI가 맞힌 결과를 전문가가 승인하면 Gold로, 틀려서 수정하면 Counter로 등록하는 식이다.

### 6\. "지속 학습"이라는 말도 두 가지 뜻이 있다

| 뜻 | 바뀌는 것 |
|---|---|
| **일반적인 의미** | 새 데이터로 **모델을 주기적으로 재학습** (A를 반복) |
| **In-context 방식에서 쓰는 의미** | 모델은 그대로 두고 **Gold·Counter·규칙·프롬프트를 계속 갱신** (D를 쌓음) |

"가중치는 고정해도 서비스는 계속 학습한다"는 말은 두 번째 뜻이다. **Continuous Learning ≠ Continuous Fine-tuning**이라고 표현하기도 한다. 문서에서 "지속 학습"이 나오면 어느 쪽인지 확인하자.

### 7\. 한눈에 비교

| | Fine-tuning | Few-shot / Many-shot | RAG |
|---|---|---|---|
| 모델(가중치) 변경 | **있음** | 없음 | 없음 |
| 바꾸는 것 | 모델의 행동·스타일 | 출력 행동 (예시로 유도) | 참고 지식 |
| 적용 속도 | 느림 (학습 필요) | 즉시 | 즉시 (색인 필요) |
| 필요 데이터 | 많은 정답 쌍 | 소수의 좋은 예시 | 검색할 문서 |
| 모델 교체 시 | **재학습 필요** | 예시 재사용 | 문서 재사용 |
| 호출 비용 | 입력 짧음 | 예시만큼 입력 증가 | 근거만큼 입력 증가 |
| 잘 맞는 상황 | 형식·말투를 깊게 고정, 반복 작업 대량 처리 | 빠른 시작, 규칙이 자주 바뀜 | 최신·사내 지식 반영 |

### 8\. 실무에서 흔한 순서

1.  **프롬프트 + Zero/Few-shot**으로 시작
2.  지식이 필요하면 **RAG** 추가
3.  예시가 쌓이면 **Gold·Counter를 RAG로 골라 넣기** (Few-shot RAG)
4.  그래도 반복 패턴에서 품질·속도가 부족하면 **LoRA/QLoRA 같은 경량 Fine-tuning**을 선택적으로

요즘은 모델이 빠르게 바뀌어서 **1~3으로 최대한 해결하고, 4는 데이터가 충분히 쌓인 뒤 필요한 곳에만** 쓰는 흐름이 많다. 반대로 Fine-tuning이 계약·요구사항으로 정해져 있는 경우도 있으니, 그럴 땐 "무엇을, 어느 범위까지(본체? 임베딩? 어댑터?)" 학습하는지 먼저 명확히 해야 한다.

### 마무리

한 줄로 줄이면, **Fine-tuning은 모델의 머리를 바꾸는 것이고, Few-shot·Many-shot·RAG는 머리는 그대로 두고 매번 좋은 예시와 자료를 건네주는 것**이다. "Few-shot 학습"의 "학습"은 Training이 아니라는 것, 그리고 "지속 학습"이 어느 쪽 뜻인지 확인하는 것만 기억해도 문서 읽기가 훨씬 수월해진다.
