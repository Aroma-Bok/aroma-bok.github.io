**개발하면서 시노님(SYNONYM)이란 개념을 처음 듣게 되면서 정리하게 되었다.**

* * *

#### **시노님(SYNONYM)?**

**오라클 데이터베이스에서의 시노 님(SYNONYM)은 다른 데이터베이스 객체(테이블, 뷰, 프로시저 등)에 대한**

**별칭(Alias)으로 사용되는 개념이다. 일반적으로 사용하는 AS(Alias)와의 차이점은 영속성인 거 같다.**

**AS는 1회성이지만, SYNONYM은 영구적으로 계속 사용할 수 있다.**

**시노 님은 다른 객체를 가리키는 이름으로, 원래 객체의 이름을 간단하게 참조하거나,**

**다른 스키마에 있는 객체에 접근할 때 사용된다.**

![](/assets/img/posts/222/1.png)

**장점**

-   **간결성 : 긴 객체 이름을 직접 사용하는 대신 간결한 이름을 사용하여 코드나 쿼리를 더 읽기 쉽게 만든다.**
-   **보안 및 권한 관리 : 시노 님을 통해 다른 스키마에 있는 객체에 접근할 수 있으므로, 객체의 소유자가 권한을 관리할 수 있다.**
-   **포팅과 유지보수 : 시노님을 사용하여 객체 이름을 중앙에 관리하면, 객체 이름이 변경되더라도 코드를 수정하지 않고도 유지보수가 가능하다.**

**시노 님(SYNONYM)을 사용하지 않는 경우**

```java
-- A 스키마에서 B 테이블을 사용하는 경우
SELECT * FROM A.B;
```

**시노님(SYNONYM)을 사용하는 경우**

```java
-- 시노님을 사용하여 B 테이블을 참조하는 경우
SELECT * FROM B_SYNONYM;
```

**시노님(SYNONYM) 조회**

```java
SELECT *
FROM ALL_SYNONYMS
```

**시노님(SYNONYM)을 사용하면 코드가 다 간결해지고 가독성이 향상된다. 테이블 이름이나 스키마 이름이 변경되더라도 시노 님만 수정하면 되므로 유지보수성이 좋다.**

**또한, 보안 및 권한 관리에서도 이점이 있다. A 스키마의 사용자가 B 테이블에 직접 접근하는 대신에 시노님을 통해 접근하도록 할 수 있다. 이로써 B 테이블에 대한 권한을 더 세밀하게 관리할 수 있다.**
