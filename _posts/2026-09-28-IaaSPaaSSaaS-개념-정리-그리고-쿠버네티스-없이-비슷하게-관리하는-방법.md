### 들어가며

"클라우드"라고 하면 보통 AWS 같은 퍼블릭 클라우드를 먼저 떠올리게 된다. 하지만 실제로는 **온프레미스에서도 클라우드처럼 운영하는 방식**이 있고, 클라우드 서비스도 **IaaS/PaaS/SaaS로 역할이 나뉘어** 있다. 여기에 쿠버네티스를 안 쓰고도 비슷한 효과를 낼 수 있는 방법까지 정리해본다.

### IaaS / PaaS / SaaS

클라우드 서비스 모델을 **"내가 직접 관리하는 범위가 얼마나 되나"**로 구분한 것이다. 위로 올라갈수록 내가 신경 쓸 게 줄어들고, 플랫폼이 대신 해주는 게 늘어난다.

-   **온프레미스**: 하드웨어, OS, 미들웨어, 앱, 데이터를 전부 직접 관리 (예: 직접 산 서버에 직접 구축)
-   **IaaS (Infrastructure as a Service)**: 하드웨어와 가상화 계층만 플랫폼이 제공, OS부터는 직접 관리 (예: AWS EC2)
-   **PaaS (Platform as a Service)**: 하드웨어+OS+런타임+스케일링까지 플랫폼이 제공, 코드/앱만 관리 (예: Red Hat OpenShift, Heroku)
-   **SaaS (Software as a Service)**: 전부 플랫폼이 제공, 로그인해서 그냥 씀 (예: Gmail, Notion)

여기서 **PaaS를 실제로 만들어주는 게 쿠버네티스**(또는 OpenShift 같은 쿠버네티스 기반 플랫폼)다. "컨테이너 기반 PaaS"라는 말이 나오면 쿠버네티스가 그 밑에서 돌아가고 있다고 보면 된다.

### 온프레미스 프라이빗 클라우드란

**온프레미스(On-Premise)**는 "내 건물/우리 회사 데이터센터 안에"라는 뜻이다. 서버를 직접 사서, 우리 회사가 소유한 랙에 꽂아넣고, 우리 회사 직원이 직접 관리한다. 반대말이 "AWS 같은 남의 데이터센터를 빌려 쓰는 것"이다.

**프라이빗 클라우드(Private Cloud)**는 "클라우드"라는 이름이 붙었다고 AWS를 쓴다는 뜻이 아니다. 여기서 클라우드는 **운영 방식**을 말한다 - 물리 서버 여러 대를 가상화해서 하나의 리소스 풀로 묶어놓고, 필요할 때마다 서버·스토리지를 유연하게 떼어 쓰고 반납하는 방식(AWS에서 인스턴스 켜고 끄는 것처럼). "프라이빗"은 이 리소스 풀을 **우리 회사만 독점적으로 쓴다**는 뜻이다.

### 물리 서버를 하나의 리소스 풀로 묶는다는 것

**가상화**란: 서버 한 대의 CPU/메모리/디스크를 소프트웨어(하이퍼바이저 - VMware ESXi, KVM 등)로 여러 조각으로 잘라서, 그 조각 하나하나가 "나는 독립된 서버다"라고 믿게 만드는 기술이다. 이렇게 잘라진 조각을 **가상머신(VM)**이라고 부른다.

**리소스 풀**이란: 물리 서버가 여러 대일 때, 가상화 소프트웨어(VMware, OpenStack 같은 것)를 깔면 이 여러 대의 CPU/메모리/디스크를 전부 더한 총합을 **하나의 큰 창고(풀)**로 취급한다. 어떤 작업이 리소스가 필요하다고 하면 **지금 여유 있는 서버 아무 곳에나 자동으로 배치**한다. 사람이 일일이 어느 서버에 올릴지 지정할 필요가 없다.

비유하면, 물탱크 여러 개가 따로 있으면 각 탱크 물만 따로 쓸 수 있다. 근데 그 탱크들을 파이프로 다 연결해서 하나의 저수지처럼 만들면, 어디서 물을 뽑아 쓰든 상관없이 **"저수지에서 필요한 만큼 뽑아 쓴다"**가 된다. 서버 리소스 풀도 똑같은 개념이다.

### 쿠버네티스 없이 쿠버네티스처럼 관리하는 방법

VM 기반 온프레미스 환경이라면, 쿠버네티스가 컨테이너한테 해주는 일(**리소스 풀링, 자동 배치, 장애 시 자기치유**)을 VM 단위로 똑같이 해주는 도구가 따로 있다.

-   **Red Hat OpenStack Platform / RHV**: KVM 기반 오픈소스 스택. 물리 서버 풀에서 VM을 자동 배치하고, 서버 하나가 죽으면 그 위 VM들을 다른 서버로 자동 재기동(HA)한다
-   **VMware vSphere (DRS + HA)**: 상용 쪽에서 제일 유명한 대안. DRS가 VM을 여유 있는 호스트로 자동 재배치하고, HA가 장애 시 자동 재기동한다
-   **Docker Swarm**: 컨테이너 오케스트레이터긴 한데 쿠버네티스보다 훨씬 가볍고 단순하다. "쿠버네티스는 너무 무겁다" 싶을 때 선택
-   **HashiCorp Nomad**: 컨테이너뿐 아니라 VM, 배치 작업까지 스케줄링해주는 범용 오케스트레이터. 쿠버네티스보다 설정이 단순한 게 장점
-   **전통적인 방식 (Ansible/Puppet + 로드밸런서)**: 오케스트레이터 없이, 정해진 서버 목록에 스크립트로 배포하고 로드밸런서로 트래픽만 분산. 자동 재배치/자가치유는 없고 사람이 대응해야 함 - 제일 원시적이지만 여전히 실무에서 많이 쓰임

### 마무리

정리하면, 클라우드는 AWS 같은 퍼블릭 클라우드만 있는 게 아니라 온프레미스에서도 "클라우드처럼" 운영하는 방식(프라이빗 클라우드)이 있고, 서비스 모델은 관리 범위에 따라 IaaS/PaaS/SaaS로 나뉜다. 그리고 PaaS를 실현하는 대표 기술이 쿠버네티스지만, VM 기반 환경에서는 OpenStack이나 vSphere 같은 도구가 같은 역할(리소스 풀링, 자동 배치, 자기치유)을 대신해줄 수 있다. 결국 핵심은 도구 이름이 아니라 **"여러 서버의 자원을 하나로 묶어서 자동으로 배분한다"**는 개념이다.
