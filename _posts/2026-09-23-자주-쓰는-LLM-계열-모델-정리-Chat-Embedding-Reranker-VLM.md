### 들어가며

오늘 RAG 파이프라인에 임베딩 모델을 붙이면서 챗 모델(Nemotron)과 임베딩 모델(nemotron-3-embed)을 같이 다뤘는데, 둘이 완전히 다른 모델이라는 걸 확인했다. "LLM"이라는 말로 다 뭉뚱그려 부르지만 실제로는 역할별로 나뉜 여러 종류의 모델이 있어서, 자주 마주치는 것들을 정리해본다.

### 1\. 생성형(Chat/Generative) 모델

흔히 "LLM"이라고 하면 떠올리는 그 모델이다. 입력 뒤에 이어질 텍스트를 예측해서 생성한다. 질문에 답하거나, 글을 요약하거나, 코드를 짜는 등 "결과물을 만들어내는" 모든 작업에 쓰인다.

-   예: GPT, Claude, NVIDIA Nemotron 계열
-   입력: 프롬프트(텍스트) / 출력: 생성된 텍스트

### 2\. 임베딩(Embedding) 모델

텍스트를 의미가 반영된 숫자 벡터로 바꾸는 모델이다. 텍스트를 생성하지 않고, 고정된 크기의 벡터 하나만 반환한다. 검색·추천·RAG처럼 "의미가 비슷한 걸 찾아내는" 작업에 쓰인다.

-   예: NVIDIA nemotron-3-embed-1b, OpenAI text-embedding 계열
-   입력: 텍스트 / 출력: 고정 차원 벡터(숫자 배열)
-   일부 모델은 질문용(query)과 문서용(passage)을 다르게 인코딩하기도 함

### 3\. 리랭커(Reranker) 모델

임베딩 검색으로 1차 후보를 여러 개 뽑은 뒤(예: 상위 20개), 그 후보들이 질문과 실제로 얼마나 관련 있는지 훨씬 정교하게 다시 채점해서 순위를 매기는 모델이다. 임베딩 검색은 빠르지만 정확도가 살짝 아쉬운 경우가 있어서, "1차로 빠르게 후보 추리기(임베딩) → 2차로 정밀하게 재정렬(리랭커)" 조합으로 많이 쓴다.

-   입력: 질문 + 문서 후보 쌍 / 출력: 관련도 점수
-   임베딩보다 느려서 전체 문서가 아니라 1차로 추려진 후보에만 적용
-   참고: 지금 쓰는 NVIDIA 무료 계정 카탈로그에는 리랭커 모델이 없다 - 개념만 알아두고, 필요해지면 Cohere Rerank 같은 다른 제공자를 찾아봐야 함

### 4\. VLM(비전-언어) / 멀티모달 모델

텍스트뿐 아니라 이미지까지 같이 이해하는 모델이다. 사진을 보고 설명하거나, 이미지 속 표·차트를 읽거나, 이미지 자체를 벡터로 바꾸는 것도 여기 속한다.

-   예: NVIDIA llama-3.2-nemoretriever-1b-vlm-embed-v1(이미지 임베딩), meta llama-3.2-90b-vision-instruct(이미지 보고 답변)
-   OCR 없이 이미지 안의 글자·레이아웃까지 통째로 이해할 수 있다는 게 장점

### 이 외에 알아두면 좋은 것들

-   STT(음성 텍스트변환)/ASR(음성인식) - 음성을 텍스트로
-   TTS(음성합성) - 텍스트를 음성으로
-   이미지 생성(Diffusion) - 텍스트로 이미지 생성 (Stable Diffusion 등)

### 마무리

정리하면 챗 모델은 "답을 만드는" 모델, 임베딩 모델은 "의미로 찾는" 모델, 리랭커는 "찾은 걸 더 정확히 줄세우는" 모델, VLM은 "이미지까지 이해하는" 모델이다. RAG 시스템 하나를 제대로 만들려면 최소한 챗 모델 + 임베딩 모델 조합이 필요하고, 검색 품질을 더 올리고 싶으면 리랭커를, 이미지가 섞인 문서를 다루고 싶으면 VLM을 추가로 붙이는 식으로 확장한다.
